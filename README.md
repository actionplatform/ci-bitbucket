# ci-bitbucket

Bitbucket Pipelines for projects generated by `action-platform`. Logic lives in [ci-scripts](https://github.com/actionplatform/ci-scripts); Pipelines cannot include a remote file, so each project carries [`bitbucket-pipelines.yml`](bitbucket-pipelines.yml) with the image for its language.

| Step | Does | Runs on |
|------|------|---------|
| `ap-check` | setup + lint + format + tests | every pull request |
| `ap-conventional-commit` | Conventional Commits since the destination branch | every pull request |
| `ap-gitflow` | branch name and merge target follow git-flow | every pull request |
| `ap-release` | version bump on `vX.Y.Z` tags (needs the repository variable `CI_PUSH_TOKEN`, an access token with write on the repository) | tags `v*` |

Variables Pipelines provides: `BITBUCKET_BRANCH`, `BITBUCKET_PR_DESTINATION_BRANCH`, `BITBUCKET_TAG`, `BITBUCKET_REPO_FULL_NAME`. Set `AP_DEFAULT_BRANCH` when the default branch is not `main`. Enable Pipelines once under Repository settings → Pipelines → Settings.

Tag `vX.Y.Z`; `v1` floats to the latest.
